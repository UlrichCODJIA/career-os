# Contributing to Career OS

Career OS welcomes focused, evidence-backed contributions.

## Before opening a pull request

1. Start from a Linear issue or open a GitHub proposal describing the problem and intended boundary.
2. Read `SECURITY.md`, the relevant ADRs, and `docs/architecture/module-boundaries.md`.
3. Keep one focused outcome per pull request.
4. Add tests for behavior and failure modes.
5. Record provenance for copied or adapted code, fixtures, schemas, and external data.

## Local checks

```bash
bun install --frozen-lockfile
bun run check
```

## Pull-request requirements

- Use an imperative title and link the tracking issue.
- Explain architecture and security impact, including relevant threat IDs.
- Include verification evidence and migration/rollback notes.
- Never commit credentials, private candidate data, production payloads, or licensed source data outside its permitted retention.
- Consequential product behavior needs explicit approval-policy and receipt tests.

## Commit and review policy

Branches should use the name generated by Linear when a Linear issue exists. Changes land through reviewed pull requests with required CI checks. Maintainers may request smaller commits or a dedicated ADR when a change alters ownership, trust, persistence, or provider boundaries.
